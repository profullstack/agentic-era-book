# Preface {#preface}

This book was written the way it describes. An engineer framed it, a handful of AI agents drafted chapters in parallel, and a human decided what made the cut. The source is plain Markdown in a public Git repository. Pandoc turns it into the HTML, EPUB and PDF you are reading. If you find a mistake, open a pull request. That is the whole publishing model, and it is also, more or less, the whole thesis.

We are Profullstack. We run roughly 170 active repositories with a very small number of humans and a very large number of agents. Some of those repos are products with paying customers. Some are experiments that never found anyone. All of them taught us something about what happens when typing code stops being the expensive part of software engineering.

## Who this is for

You write software for a living, or you manage people who do, and you have noticed that the ground moved. Maybe you use a coding agent every day and want a system around it instead of a pile of habits. Maybe you are skeptical and want to see what the workflow looks like from people who bet a company on it. Either way, you already know how to program. This book is about everything around the programming: how work gets framed, split, checked, shipped, paid for, secured and announced when the code itself is cheap.

## What this book is not

It is not a prompt cookbook. Prompts go stale in weeks. It is not a survey of every agent framework on GitHub. And it is not neutral. We build tools for this way of working, we use them every day, and we are going to tell you about them. When a tool of ours fits the problem, you will see it in a box like this:

::: tool
**Tool: example**

What it does, why we built it, and the one command to install it. Everything in these boxes is free to try, and most of it is open source.
:::

House rules, the things we learned by breaking production, look like this:

::: rule
**House rule**

A merged pull request reaches nobody until the release is cut.
:::

We have tried to be honest about status. Some of these tools are mature. Some are early. Where something is a beta, or where a claim in a README got ahead of the code, we say so. If we got it wrong, the repository is linked on the title page.

## How to read it

Part I is the argument: what changed and why the job is different now. Part II is the workbench: the terminal, the browser, the pairing session and the stack. Part III is the loop that turns a request into a release. Part IV covers running a fleet of agents for real: keys, money, identity and compute. Part V is about people, including you. The appendices list every tool with its install command, and a glossary for when the jargon gets thick.

Read it front to back, or jump to the chapter for the problem you have today. Then go ship something.
